# LiteMonitor 蓝牙电量插件 (v1.4.1)

在 LiteMonitor 里显示**当前真正连接中**的蓝牙设备电量，按电量从低到高排列（最多 6 行），
低于阈值变红（40~59% 黄色），一眼看到该给谁充电。面板和 Windows 任务栏都能显示。

- 数据来源：BLE GATT Battery Service（0x180F / 0x2A19），本地服务 `127.0.0.1:18923`
- 在线判定：蓝牙连接状态（ConnectionStatus）——历史配对但已断开的设备不显示
- LiteMonitor 插件只能发 HTTP 请求、不能执行本地命令，所以本地服务是必需的

## 显示行说明（设置 → 监控项 里可单独开关面板/任务栏）

| 行 | 内容 |
| --- | --- |
| dev1 | 在线设备中电量最低的（最先爆红） |
| dev2~dev6 | 其余在线设备，电量从低到高 |
| 蓝牙在线 | 当前在线设备数 |

dev1/dev2 默认显示（面板 + 任务栏）。以后在线设备超过 2 台，去
LiteMonitor 设置 → 监控项 把 dev3~dev6 打开即可；关闭某行 = 不显示该槽位。
任务栏上显示为紧凑格式 `BT1  44%`（标签来自插件 short_label）。

## 插件设置（设置 → 插件 → 蓝牙设备电量）

| 输入 | 说明 |
| --- | --- |
| 爆红阈值(%) | 电量低于此值显示红色，默认 20（<warn 红，<warn+20 黄，其余绿）|
| 本地服务端口 | 需与 `BluetoothBattery.ps1 -Port` 一致，默认 18923 |

两个都是**全局作用域**，和「本地服务端口」一样是普通输入框，直接改数字即可。
（v1.3 之前爆红阈值是 target 作用域，被塞进「目标」区块里导致填不了 —— v1.4 已修正。）

## 接口

- `http://127.0.0.1:18923/battery?warn=20` — 槽位聚合（warn = 爆红阈值）
- `http://127.0.0.1:18923/all` — 全部设备原始数据（调试）

命令行：`BluetoothBattery.ps1 -Once` 打印快照；`-Serve -Port 18923` 起服务。
**必须 `-MTA`**（STA 下 WinRT 异步回调全部超时）。
`run-service.ps1` 是看门狗：端口空闲才重启服务，可重复运行不会打架。

## 已知限制

- 经典蓝牙（耳机/音箱）无标准电量服务，读不到。
- 罗技 MX Master 3S 等用私有 HID++ 协议上报电量，标准 GATT 读不到；
  2.4G 优联接收器同样需要 HID++（本机 PnP 无任何 HID 电池设备）。
  要支持得实现 HID++ 协议，EasyBluetooth 就是这么做的。
- 设备休眠断链期间不显示（这是判定机制的预期行为，不是 bug）。
- **插件无法独立成组**：LiteMonitor 把所有插件输出硬编码归到 `DASH.`（仪表盘）分组，
  `GroupAliases` 只能整组改名（会连默认项一起改）。所以蓝牙行只能待在仪表盘区。

## 故障排查

| 现象 | 处理 |
| --- | --- |
| 蓝牙行显示 ❌/空白 | 服务没起：双击 `run-service.ps1`，或下次登录会自动拉起 |
| 设备时有时无 | BLE 休眠断链，正常 |
| 阈值填不了 | 确认插件是 v1.4（`scope` 为 global），旧版重启 LiteMonitor 重新加载模板 |
| 想让别的行上任务栏 | 设置 → 监控项，勾对应行的「任务栏显示」 |
| 服务换端口 | `-Port 18924` 启动 + 插件设置里「本地服务端口」同步改 |

settings.json 备份：`settings.json.bak-before-taskbar`（开启任务栏前自动留的）。
